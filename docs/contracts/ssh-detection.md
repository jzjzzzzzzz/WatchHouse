# SSH 关联规则 v1

规则 ssh.failures-followed-by-success.v1 在同 host、boot、用户名和来源 IP 上，观察窗口内至少 threshold 次失败，随后出现成功认证时产生 high priority 调查 finding。

默认窗口五分钟、阈值五次。失败可以是 password/publickey，成功同样支持两者，不要求方法相同。不同用户的 NAT 共享 IP 不合并。boot 不同不关联。任意成功都会结束此前的连续失败段，包含低于阈值的段。

窗口左边界包含在内：恰好五分钟前的失败计入。证据保留最近 threshold 次失败和成功事件 ID，不声称包含全部失败。finding 标识绑定 rule ID、窗口、阈值和成功事件；同输入、同配置重放得到同标识。

处理器单线程使用，输入必须按 observed_at 非递减排列。保留窗口内 event ID 去重；同 ID 但内容冲突报错。过期后重放旧事件会因乱序报错，不保证无限历史去重。乱序、不支持的事件和容量满都是显式错误；不能将拒绝解释为无攻击。

默认最多保存 8192 个窗口内事件。计数状态和证据有界，但不提供持久化、跨重启状态或上报队列。上限只描述单规则内存状态，不是整个 agent 存储上限。

finding 说明需要调查，不宣称账户已失陷，不执行封禁或响应动作。此规则会遗漏其他用户名、不同 IP、分布式或不产生支持日志格式的攻击。当前只有受控 fixtures，不能据此报告生产检出率或误报率。
