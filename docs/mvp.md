# 第一版范围与验收

## 部署范围

- 一个固定 Ubuntu LTS 版本，开始实现时锁定发行版、内核和 Docker 版本并记录到部署清单。
- 一台管理节点：Watchhouse 控制端、PostgreSQL、CLI/API、外部探针。
- 一台受管 VPS：原生 systemd agent、受限 helper、Nginx、Docker workload、应用 PostgreSQL。
- 一台按需启动的隔离恢复 VM。没有生产 DNS、通知、webhook 或写入权限。
- VPS 上实际使用一个现有自托管服务；staging 用相同部署模型和脱敏测试数据。

管理节点与受管 VPS 分离。外部探针不运行在受管主机上，并通过其公网入口访问；不能用 localhost 检查冒充公网验证。第一版不宣称多地域或所有网络视角的可达性。

## 三类检测

### 一 未声明的监听或端口发布

声明允许的服务、监听地址和端口。采集宿主 socket、进程、systemd unit 和注册容器的 published ports。

finding 至少包含：预期状态、当前状态、采集时刻、socket/容器来源、owner 或 unknown、外部 TCP 验证结果。

区分三个结论：存在监听、配置了端口发布、从指定探针位置实际可达。不能相互替代。没有足够权限或进程已退出时必须标记 unknown。

### 二 SSH 异常认证序列

从 journald 中解析失败和成功认证。初始可配置规则：同一来源地址在五分钟内失败达到阈值，随后出现成功认证时提升调查优先级。

按用户、来源和时间保留原始事件引用。对 NAT、多用户来源、合法重试提供正常 fixtures。规则输出“需要调查的关联”，不输出“已经被攻破”。第一版不自动封禁来源地址或禁用账号。

### 三 Nginx 配置偏移或服务异常

对受管配置记录摘要；获取 unit 状态、退出信息和相关 journal；结合外部 DNS、TCP、TLS、HTTP 分层探针。

输出可解释证据：配置是否偏移、进程是否运行、监听是否存在、upstream 是否可达、TLS 是否有效、HTTP 是否通过。不能只用一个红色 health 状态代替定位信息。

## 一个生产变更动作

**恢复预先注册的 Nginx 配置版本并 reload。**

- 仅操作专属配置目录；不是全机配置编辑器。
- 版本来自部署时由管理员登记的只读 approved bundle。API 不能上传任意“已知良好”配置。
- plan 包含主机、资源、当前摘要、目标 bundle 摘要、证据引用、有效期、检查项和回滚信息。
- operator 批准；agent 在执行前重新读取当前摘要、版本和本地 allowlist。
- 保存操作前状态；写入与状态持久化顺序明确；执行 `nginx -t`，通过后 reload。
- 内部与外部检查全部通过才记录 verified。
- 验证失败或等待外部确认超时，恢复操作前状态，再次测试、reload 和验证。
- 回滚仍失败必须记录 rollback_failed 并告警，不假装恢复成功。

配置 rollback 只针对这个明确资源，不承诺数据库 schema、软件更新或所有系统改动都可逆。

## 一条恢复演练路径

应用 PostgreSQL 先做一致性逻辑导出，再用 restic 备份导出物和版本化配置。不能直接复制正在运行的数据库数据目录并称为可靠备份。

恢复到隔离 VM，核验数据库导入、schema、测试数据约束、应用启动和业务读取。记录备份时间点、恢复后数据时间点、开始/结束时刻和业务检查结果。

第一版选择逻辑恢复，不承诺 PITR；RPO 依据实际恢复数据点计算，不仅依据备份任务调度。

## 身份与权限

- agent 通过 mTLS 注册身份；证书必须绑定 host_id，身份不能由请求 body 自报。
- 人类 CLI 使用独立客户端身份，服务端配置 viewer、operator、admin 的身份角色映射。
- viewer 只能查；operator 可审批允许的动作；admin 管理注册与策略，但 API 无权扩大主机本地 helper 的动作边界。
- agent 不能审批，人类身份不能伪装为 agent。支持吊销注册和更换证书；完整自动证书生命周期放到后续。
- 第一版无浏览器登录，避免为了展示 auth 搭建完整身份提供商。

## 系统自身的可观测性

结构化日志串联 event_id、finding_id、plan_id、command_id。提供 metrics：采集延迟、上报失败、队列长度、丢弃数量、规则耗时、动作结果和验证时长。

无心跳、日志解析失效、权限不足、队列满不是“主机安全”，而是可见的观测故障。提供数据保留和轮转机制，不无限积累日志。

## 验收目标

以下目标必须附环境和测试结果，当前均未测量。

| 验收项 | 通过条件 |
| --- | --- |
| 干净部署 | 空白真实 Linux VM 可按文档部署；再次执行配置流程无意外改动 |
| 检测 | 三类真实场景均产生 finding，并能追溯原始事件；正常 fixtures 不触发相应高优先级规则 |
| 延迟 | 两节点测试、20 events/s 持续 10 分钟时，受控场景发现延迟 p95 不超过 30 秒；另行报告资源占用 |
| 断网 | 10 events/s、断网 10 分钟、事件大小不超过 2 KiB 的测试中，100 MiB 本地队列可补发；不重复生成 finding |
| 队列满 | 达上限时可观察到丢弃计数与时间范围，不声称完整采集 |
| 权限 | viewer、错误主机身份、过期审批、重放审批和越界动作全部拒绝 |
| 状态改变 | 审批后配置再次改变，旧 plan 拒绝执行，必须重新取证与审批 |
| 幂等 | 同一 command_id 重发不重复产生变更；崩溃后的未决结果经重读状态判定 |
| 回滚 | 故障注入导致验证失败后，恢复前态并验证；另有回滚失败负例 |
| 恢复 | 隔离实例通过数据库与业务检查；小型测试数据集恢复目标 10 分钟内，公开数据量和实测值 |
| Demo | 四分钟内展示真实异常、证据、拒绝或审批、修复和外部验证 |

MVP 完成要通过以上测试，不以 dashboard 完成或一次正常演示作为结束标准。
